# Cx 负载保护与参数结构

## 原版来源

`game/DC4_FD.exe` 的 SHA-256：

```text
db175d1d01c81822fd099d4a435c1bc2d3bdf0486e2738002d1241f592361a8e
```

该 EXE 的文件偏移 `0x2F1150` 存放 zlib 流，压缩长度 51,523 字节，展开为 105,984 字节的 PE32 模块。模块内部名称为 `cxdec.tpm.dll`，导出 `V2Link`；其 SHA-256：

```text
c28025c7452b63e22b2841c4150a9965357196d3b23ad8e3b58a9d607c6827f4
```

`main_key.py` 按有效 zlib 流、PE 标记、模块摘要和特征识别此模块，再解析记录；不把上述物理偏移直接当作提取入口。模块本体和反编译数据库仅用于本地调查，不提交。

## 参数记录

模块从 `PARAMS` 开始顺序读取记录。每条记录结构为：ASCII 名称、一个 NUL、两字节小端负载长度、负载；记录组由空名称结束。

| 记录 | 模块内文件偏移 | 长度 |
| --- | --- | ---: |
| `PARAMS` 负载 | `0xD7C1` | 22 |
| `TABLE` 负载 | `0xD7DF` | 4096 |

`PARAMS` 原始内容：

```text
06 07 05 00 02 03 04 01 02 03 01 00 05 04 02 01 00 00 d4 01 2a 00
```

| 负载偏移 | 含义 |
| --- | --- |
| `0..7` | 原生八分支选择值排列 |
| `8..13` | 原生六分支选择值排列 |
| `14..16` | 原生三种初值选择排列 |
| `17` | 表与随机数模式标志，本作为 `0` |
| `18..19` | 分界掩码，小端 `0x1D4` |
| `20..21` | 分界增量，小端 `0x2A` |

按通用 Cx 操作语义转换后，三种初值顺序为 `[2,1,0]`，六分支顺序为 `[4,3,2,5,0,1]`，八分支顺序为 `[1,4,5,6,7,3,0,2]`。随机数使用 32 位线性同余序列。

`control_block.bin` 保存 `TABLE` 的原始 1024 个小端无符号整数；本实现按原值查表，不对整个控制表取反。控制表 SHA-256 为：

```text
18b362bb9fc0c85ac8e5264c27b5f7faec02deda294a8d5dde276e64640d7ab8
```

## 过滤语义

Cx 以条目的 `adlr` 值生成运算序列，按 `(adlr & mask) + offset` 把逻辑内容分为两段，并对两个指定字节位置施加附加异或。第二段使用 `adlr ^ (adlr >> 16)`。原生实现中两个字节位置相等时，后一个位置递增；`65535` 递增到 `65536`，不按 16 位回绕。

内嵌模块初始化函数相对地址 `0x3100` 读取记录并注册 XP3 过滤回调；`0x4C50` 实现随机数生成，`0x19F0` 设置分界参数，`0x1C80` 初始化每段异或及字节位置。静态分析以模块首选基址 `0x10000000` 为准。

原版 XP3 读取路径按过滤回调工作，不能单凭重建包未设置保护标志就断定运行时会跳过该回调。新补丁加载策略须独立验证。

## 验证边界

`docs/decryption_validation.json` 记录五个 XP3 中的 11 个代表条目，包含完整原始 Adler32 比较。三张 PNG 经 Pillow 完整解码，两段 Opus 经 FFmpeg 完整解码；文本封装严格解码为 UTF-16，TJS2 和 PSB 在本阶段检查头结构。

这些结果验证本作参数和代表负载的解密，尚不替代全部资源覆盖、PSB 可编辑回环、运行时中文显示或签名强制性验证。
