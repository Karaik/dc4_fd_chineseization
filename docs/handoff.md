# 汉化素材交付与回收

本文件保留技术回收流程。归档后的源码不附带素材 ZIP 或解出的文本；原记录中的 `tmp/` 交付包与临时证据已清理，使用工具时先从本地原版准备输入并自行指定实际交付包。

汉化人员拿到的 ZIP 只含 `文本/`、`图片/` 和根目录注意事项。中文密码 ZIP 已用 WinRAR 6.20 及更新版本完整解压、逐文件核对；部分解压器使用系统代码页解释中文密码，不保证能够打开同一份包。

## 汉化人员交回内容

只需交回修改过的文件，保留 ZIP 中完整的相对路径。文本使用 UTF-8，仅修改译文；PNG 保留文件名、像素尺寸和透明通道。不要平铺图片，不要把不同作品的文件混在一起。

`.tlg.png`、`.jpg.png` 是程序提供的编辑格式，交回时完整保留双后缀。原 JPEG 不支持透明，编辑结果必须保持不透明；程序回写为质量 100、无色度抽样的真实 JPEG，仍有 JPEG 固有的像素误差。光标的多个尺寸保留在原 `.cur` 目录内，程序保留热点及未改帧。PIMG 的图层顺序、坐标、共享资源、原包装和未改图片均由工程保留，交图人员不用回封。

## 程序侧绑定实际交付包

先安装 `requirements.txt` 的固定依赖。原版解包、PIMG 导出和脚本 JSON 缓存按项目构建文档准备好，再对实际交出去的 ZIP 建立一次本地清单：

```powershell
python .\main_handoff.py catalog --package .\tmp\handoff.zip --password "your-password"
```

默认清单位于 `solution/patch/handoff_catalog.json`。它绑定本作、实际 ZIP、原始资源、每张图片的尺寸和完整 RGBA 像素摘要、文本基线、PIMG 结构以及光标各帧与热点；它是程序保留的本地输入，不交给翻译或嵌字人员修改。建立清单时实际解密并核对全部文件，不按缓存文件名猜测资源身份。工程移动后，项目内相对路径仍可使用。交付包变化后必须重新建立清单，不能跳过基线检查。

## 导入部分返回文件

把交回的目录或 ZIP 放在项目内可读位置，然后执行：

```powershell
python .\main_handoff.py import --input .\tmp\returned --output .\solution\patch\work\return_checked
python .\main_build.py --handoff .\solution\patch\work\return_checked
```

返回 ZIP 若加密，给 `import` 添加 `--password`。输入目录直接包含 `文本/`、`图片/`，不再多套一层压缩包名字。仅使用实际交付清单中的文件；未知文件、路径跳转、链接、重复路径、尺寸变化、改动源文或 ID 都会拒绝。

导入只在新的 `solution/patch/work/return_.../` 中建立候选，复制当前正式译文和静态补丁作为基础，并加入此次返回的修改。它不回写 `game/`、正式译文、图片编辑基线或正式静态资源。PNG 按像素判定变化，只有重新保存但像素未改的文件不会被误当成补丁。

候选包含完整文本、验证过的静态覆盖、显式清单和逐项摘要。`--handoff` 构建核对这些输入的完整集合与摘要；不会再导出或改写正式文本。构建前依旧执行项目的旧生成物清理，预览用 `--dry-run`，保留旧验证副本用 `--keep-previous-outputs`。

## 系统文字和冲突审核

翻译人员只改 `translation`，不改 `enabled`。原来禁用的整篇文档或 TJS2 常量发生变化时，默认导入会列出待程序审核的位置并停止。程序确认这些条目确实用于显示，且逻辑字符串、资源键和控制序列没有误译后，以新的输出目录重新执行：

```powershell
python .\main_handoff.py import --input .\tmp\returned --output .\solution\patch\work\return_reviewed --reviewed-system-edits
```

该开关仅在候选中启用实际修改的条目，后续仍通过原有结构、插值、标签和源字段守卫。它不代表自动确认所有含日文的常量都能翻译。

当前正式静态补丁与返回资源内容冲突时默认拒绝。确认此次返回应替换它后，添加 `--replace-existing-static`，也只替换新候选里的副本。已有译文自交付后变化时先处理冲突，不静默覆盖。

## 资源回写与验证

- 普通 PNG 保持原资源路径；背景和 CG 的归档分组只用于交付，程序不会把归档名误塞进原资源路径。
- TLG 保持原 TLG5/TLG6 主版本和外壳，重新解码比较整图 RGBA，包含透明像素下的 RGB。
- JPEG 使用真实 JPEG 编码并记录误差，不能只改后缀冒充；本作当前交付没有 JPEG，该格式的真实引擎验证在 D.C.5 to 4 完成。
- CUR 保留全部帧、尺寸、热点及未修改帧，重算表项与偏移；用原生 Windows 载入再核对。
- PIMG 从保留结构恢复完整输入，仅替换返回的 PNG；重封后重新解包比较像素、层序、坐标、元数据和引用。
- 脚本复用现有 ID、源文和控制码检查，回编后重新反编译比较；所有覆盖文件入 XP3 后再次重读比对。

D.C.4 FD 使用完整路径精确覆盖，保持原目录以便准确对应原资源。

本轮证据汇总见 `handoff_validation.json`。技术回环验证不代表正文已翻译、全部系统常量可译，或所有剧情路线已完整游玩。
