# XP3 索引与补丁封包

## 已确认的结构

本作五个原版包使用标准 XP3 标识 `58 50 33 0D 0A 20 0A 1A 8B 67 01`。头部 `0x0B` 为索引位置；本作另有 `0x80` 索引转向记录，最终索引使用 zlib 压缩。

索引采用长度限定的块结构。`File` 内的 `info` 保存保护标记、声明长度及 UTF-16LE 文件名，`segm` 保存分段位置与长度，`adlr` 保存文件哈希。索引中的名字可直接读取，无需运行游戏恢复文件名。

五包共 20,006 项，其中 20,001 项带保护标记。各包还有一项保护告示：其 `info` 声明长度与 `segm` 长度不一致。读取索引时保留这些原始元数据；内容提取必须检查分段长度，不能把异常告示当成成功解密的资源。

## 实现边界

`solution/unpack/xp3.py` 提供：

- `read_index(path)`：只解析索引与分段边界，不读取或解密资源负载。
- `extract_entry(path, entry, scheme)`：按分段解压，并通过本作独立验证的解密方案读取受保护负载。
- `extract_archive(...)`：在写入前检查全部选中路径、重复名字及目标冲突；默认保留已有文件。
- `pack_xp3(...)`：生成标准无保护补丁包，支持独立控制索引和负载压缩。

读取索引成功不代表保护方案已实现。没有显式解密方案时，受保护条目会报错。文件哈希是否可作为明文校验和必须依据本作验证；回解自建无保护补丁包时启用校验和检查。

运行时自有补丁流使用无压缩索引、无压缩单段负载及 `info.flags=0`。原版读取器的提取过滤器不能仅靠这个标记假定跳过，最终加载须由本作运行时实现验证。

## 回归

在项目根目录运行：

```powershell
python -m unittest discover -s tests -v
```

独立构造的压缩包样本覆盖 Unicode 路径、损坏索引、校验和错误、路径越界、已有文件保护及显式解密要求。封包回环同时检查空文件、二进制文件和有无压缩的组合。
