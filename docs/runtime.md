# 运行时构建与加载

## 文件接口

所有命令以本作项目根目录为基准。

```powershell
python .\solution\runtime\probe.py
python .\solution\runtime\build.py
```

需要 Windows 上的 MSVC x86 C++ 构建工具、Python 3.10 以上及 `pefile`。构建器通过 `vswhere` 定位编译环境，也保留标准安装路径回退；不将本机编译器绝对路径作为工程依赖。源码位于 `solution/runtime/src/`，全部编译与测试产物写入 `solution/runtime/out/`；静态调查输出位于 `solution/runtime/work/`。工作目录与源码分离，构建不执行删除操作。

供完整构建器调用的接口为 `build(out: Path, verify=True)`。默认同时编译独立流测试，生成 `runtime_summary.json` 并验证产物均为 x86，DLL 只导出 `StartRuntime`。这些验证不启动游戏。

`build` 和 `--out-dir` 只接受本项目 `out/`、`solution/runtime/out/` 或 `solution/runtime/work/` 内的目录；验证先于目录创建和编译。拒绝维护输入、项目外路径、`..`、异常 Win32 名称，以及路径祖先或已有输出树中的符号链接、目录联接和其他重解析点。输出边界测试可单独运行：

```powershell
python -m unittest solution.runtime.test_build -v
```

最终运行目录为：

```text
DC4_FD.exe
DC4_FD_chs.exe
dc4_fd_chs.dll
data.xp3
其他原版资源与 plugin/
chs_patch/
  patch.xp3
  config.ini
  launcher.log
  runtime.log
savedata_chs/
```

原版 EXE、DLL、XP3 及其签名文件保持原字节。`DC4_FD_chs.exe` 挂起启动同目录的 `DC4_FD.exe`，显式加载 `dc4_fd_chs.dll`，在加载器锁以外调用 `StartRuntime`；仅初始化成功后恢复主线程。失败时停止该新建进程并报告错误，不静默继续原版启动。窗口标题沿用原游戏。

挂起进程尚未建立模块列表时，启动器从目标进程的映射镜像读取 `ntdll` 导出表，用一次 `RtlExitUserThread` 远程线程完成系统加载器初始化，再按目标模块实际基址定位 `LoadLibraryW`。整个过程保持主线程挂起，不执行游戏主入口。独立自编译宿主测试已验证，DLL 初始化先于宿主入口。

启动器固定附加引擎原生参数 `-datapath=$(exepath)\savedata_chs`；拒绝用户再传入冲突的 `-datapath` 参数。存档目录的最终实际创建、保存与重读须由游戏冒烟验证确认。

```powershell
.\DC4_FD_chs.exe --check --no-dialog
```

`--check` 只预检四个必要输入及 `StartRuntime` 导出，不启动游戏，也不等价于成功注入。`--no-dialog` 将错误交给退出码和日志，适合自动验证；`--wait` 启动游戏后等待其退出并传回退出码。

## 补丁包约束

运行时只读取 `chs_patch/patch.xp3`。该文件必须是标准 XP3 头、一个未压缩索引、每项一个未压缩且未加密的段；`info.flags=0`，三处长度一致，并包含正确的 `adlr`。运行时验证索引和段边界、文件名、重复路径及每项 Adler-32，再将整个补丁包保持为只读内存；包上限为 512 MiB。

原版 XP3 流会无条件调用已安装的解密过滤器。新包因此不能直接交给原生 XP3 流。此实现返回自有 `tTJSBinaryStream` 兼容流，保留原始补丁字节，支持读取、定位、长度查询和析构；不经过原版过滤器。未命中的资源继续走原版入口。

覆盖以完整资源路径精确匹配，比较时忽略大小写。输入支持本作协议形式 `arc://./...`、`archive://...xp3/...`、原生 `...xp3>...` 和无协议相对资源名。拒绝绝对路径、空路径段、`.`、`..` 和内嵌空字符；不访问包外文件。默认禁用文件名回退，避免不同目录同名资源互相覆盖。

资源名校验与 Python XP3 读取器一致：同时拒绝路径段尾部的点或空格、Win32 保留设备名、控制字符和保留标点。设备名测试只调用字符串校验，不打开设备。

## 字体与日志

`solution/runtime/config.ini` 提供默认配置：

```ini
[runtime]
fontname=Microsoft YaHei
fontpath=
charset=134
basenamefallback=0
loglevel=1
```

包含非 ASCII 字符时，配置应保存为带 BOM 的 UTF-16LE。`fontpath` 可指向发布根目录下的相对字体文件，使用进程私有字体加载；空值使用系统字体。运行时拦截 Unicode 字体创建与枚举，保留竖排字体的 `@` 前缀。没有安装全局字体，也没有改动系统代码页；文本编码仍由脚本格式决定。最终字体覆盖范围与中文字形以游戏显示验证为准。

`launcher.log` 记录预检、目标进程编号、注入初始化和恢复结果。`runtime.log` 记录实际入口相对地址、封包项数、导出接口绑定、精确资源覆盖和字体创建。`loglevel=2` 额外记录未命中资源；英文日志便于脚本检索。

两个日志通过 `_wfsopen(..., _SH_DENYWR)` 打开，允许外部工具读取，继续排斥第二个写入端；每条运行时日志写入后立即刷新。构建验证使用独立写进程确认保持打开时可读、已刷新内容可见，以及第二写入端被拒绝。

## 本作静态证据

当前原版 `DC4_FD.exe` SHA-256：

```text
db175d1d01c81822fd099d4a435c1bc2d3bdf0486e2738002d1241f592361a8e
```

EXE 为普通 x86 PE32，首选基址 `0x400000`，入口相对地址 `0x23B053`。存在完整的 MSVC 启动代码、正常代码与重定位节、13 个导入库共 314 个导入项，未见整个 EXE 被壳包装的证据。内嵌压缩模块属于资源保护方案，不能据此推断负载已解密。

| 对象 | 本作实际相对地址 | 证据 |
| --- | --- | --- |
| `TVPCreateStream` | `0xF3A0` | 长签名在可执行节唯一命中，`ECX` 为资源字符串，`EDX` 为标志；内部处理归一化、归档分隔符和流创建 |
| 插件导出器获取函数 | `0x21710` | 唯一短签名；首次调用解压导出名表并返回静态接口；普通插件、内存模块和视频插件加载路径均调用此函数 |
| 插件导出名表 | `0x3AF5B8` | 5087 字节 zlib 解压为 41989 字节，共 649 个名字；指针表起于 `0x3AEB90` |
| 字符串访问接口 | `0x1C210` | 名字表第 149 项，接口为 `const tjs_char * tTJSString::c_str() const` |
| XP3 过滤器设置接口 | `0x1DBA0` | 名字表第 283 项，写入全局过滤器指针 |
| XP3 全局过滤器指针 | `0x3B82C0` | 原生 XP3 流读取后在指针非空时无条件调用 |
| 原生 XP3 流读取 | `0x37700` | 回调传入 24 字节结构，包含流偏移、缓冲区、长度和文件哈希 |

启动器从全新 DLL 导出定位初始化入口；运行时每次在主模块的可执行节重新搜索，要求两个签名各自唯一，不把上述地址直接作为写入偏移。接口初始化只查询本作已存在的字符串访问接口。未移植其他作品的 `KrkrSign` 补丁或猜测偏移；当前方案通过保留原文件、显式注入和独立补丁流处理加载。`.sig` 是否另有内存检查或外部启动器限制仍需实际启动验证。
